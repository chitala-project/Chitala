# Safety traceability matrix

Each hazard of [the hazard log](hazard-log.md), the requirements that answer it, where they are enforced, the tests that prove them and the further evidence.

- **Requirement**: a Safety rule of [spec 17](../../specs/17-safety.md) (`SAFE-n-…`), or a spec or an article of the Security Constitution (C-n).
- **Tests**: test functions by name, in backticks; `grep -rn 'fn <name>' crates` finds each one.
- **Evidence**: beyond the tests:
  - mutation runs: faults put back into the code on purpose, which the tests must catch. Each set named in backticks is in [`mutation/sets/`](../../mutation/sets/); anyone can run it again (`python3 mutation/run.py <set>`), and CI runs every set weekly;
  - adversarial suites;
  - audits;
  - lab runs on real devices.

[`scripts/check-safety-case.py`](../../scripts/check-safety-case.py) checks the matrix on every change: every hazard has a row, every rule exists, every test exists, every mutation set exists. Whether a test proves what its row says is a reviewer's question.
